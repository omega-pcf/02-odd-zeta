# Project Documentation

This directory contains technical documentation for the shared build and release pipeline.

## Structure

```
docs/
├── README.md          # This file
├── architecture.md    # Release system architecture
├── citations.md       # CSL single-source citation pipeline (§1–§7) + witness index (§8)
├── counts.md          # Generated counts ledger (pnpm run counts; never edited by hand)
├── installation.md    # Prerequisites and setup
├── numerical-port.md  # NUMPORT-001: living coverage tracker of the hipotesis/pruebas → tests port campaign
├── usage.md           # Build and release commands
├── witness-contract.md # The single living norm: rationale, standard (§6) and wave-brief shape (§10)
├── witness-decisions.md # The family ledger: one row per question, open and ruled
├── witness-inventory.md # This repository's census of marks, generated from a measurement
└── reports/           # Specific, repository-tied reports (dated, id'd)
    └── README.md      # Reports convention (template) + index of this repository's reports
```

`docs/` itself stays generic (rules and rationale, portable across the
sibling repositories); anything tied to one repository state — per-site
inventories, decision logs, verdict tables — goes to `docs/reports/`.

## Contents

- **architecture.md**: Tech stack, execution flow, reproducibility measures, scripts structure.
- **citations.md**: How `citation.csl.json` (179 records) drives the bibliography,
  CITATION.cff and .zenodo.json (§1–§7); §8 is an index: it points to the family standard in
  `witness-contract.md` §6 and to this repository's measured state in `docs/reports/`.
- **counts.md**: The measured counts of this repository — the pytest suite
  totals (`pytest.collected`, `pytest.not_slow`), the Lean source statistics of
  `lean/F1_pentagonal_descent_UNIFIED.lean` and the `images/` inventory — with the command that measures each.
  Generated by `pnpm run counts`; `pnpm run counts:check` (inside `validate`) fails when it drifts.
  The marked regions live in `tests/README.md` (`commands`, `suite-total`,
  `suite-not-slow`); the manuscript itself does state counts in prose — the
  appendix's corpus counts (proved, open and classical statements) and the
  forty `\witness[\testref{…}]{N}` anchors that cite test ids — but those live
  outside the mechanism, which measures only the ledger's counters.
- **installation.md**: Prerequisites and setup instructions.
- **numerical-port.md**: `NUMPORT-001`, the living tracker of the port campaign that moves the
  numerical evidence of `hipotesis/pruebas/` into `tests/` — the destination convention (F10 pattern,
  one entrypoint `uv run pytest tests/`), the master table of the 83 scripts reconciled against the
  suite's 132 tests, and the sub-tables of `salidas/`, `datos/`, the orphans and the blockers.
  It records state only: neither `hipotesis/pruebas/` nor `tests/` is edited from it.
- **usage.md**: Daily workflow, conventional commits, build and release commands.
- **witness-contract.md**: The single living norm of the witness marks — the rationale (§1–§5,
  §7), the standard itself (§6: precedence, syntax, placement, naming, grammar and the writing
  rules, the star, typography, gates, alphabet, the quantified inline / own-line criterion §6.10,
  the own-line rendering form §6.12, the ledger segmentation §6.13) and the required shape of a
  wave brief (§10). Portable across the family: byte-identical and manifest-pinned.
  - **witness-decisions.md** is the decision ledger, one row per question (a count is never a
    row); **witness-inventory.md** is this repository's generated census of marks.
  - **reports/**: Specific reports — the witness reconciliation (F8-001), the tier-use migration
    map (FTI-001), the author text changes (F12-001), the provenance inventory (F9-001), the
    pytest suite port (F10-001), the citation verification (CIT-003) and the merge closure
    (MRG-001), plus the working papers promoted from scratch — the witness
    specification (`WIT-SPEC-002`), the witness inventory the suite cites
    (`INV-WIT-001`), the own-line rendering probe (`PROBE-001`) and the
    numerical-scripts reconciliation (`SCRIPTS-RECON-003`). The convention (naming, ISO header, index format) and the index of this
    repository's reports are in `reports/README.md`.

## Conventions

All commits follow [Conventional Commits](https://www.conventionalcommits.org/):

```
<type>(<scope>): <description>
```

**Common types:** `feat`, `fix`, `docs`, `refactor`, `chore`.
