# Citations Pipeline — Best Practices

| Field | Value |
|---|---|
| **document** | `docs/citations.md` |
| **status** | active |
| **version** | 1.0 (port of the family guide, adapted to this repository's measured state) |
| **date** | 2026-11-23 |
| **scope** | The citation pipeline of `02-odd-zeta` (179 records) and the witness contract its manuscript applies (alphabet P and N) |

This document describes how citations flow from a single source of truth to
the PDF, CITATION.cff, and .zenodo.json, and the conventions for adding new
references. The row-by-row chain of every generated file (which source feeds
which generator, and what it writes) is
[`architecture.md` §Sources of truth](architecture.md#sources-of-truth).

Two companion documents hold what this one deliberately does not: the
**justification** of the witness device is argued in
[`docs/witness-contract.md`](witness-contract.md), and the **concrete
per-site material** — inventories, sentence tails, applied states, verdict
tables — lives in [`docs/reports/`](reports/README.md). This file states
only the generic, portable rule, plus the facts of this repository that the
rule is applied to (every count below was measured on 2026-11-23).

## 1. Single source of truth

`citation.csl.json` (a CSL JSON array of **179 records**) is the ONLY place
where citation metadata is edited.

Derived files — never edit by hand, always regenerated by the build:

| File | Produced by | Purpose |
|---|---|---|
| `src/bibliography.bib` | `scripts/tasks/citation.ts` (`data.format('biblatex')`) | BibLaTeX database consumed by biber |
| `CITATION.cff` | `scripts/tasks/citation.ts` (CSL→CFF mapping via citation-js) | Software/dataset citation metadata |
| `.zenodo.json` | `scripts/tasks/citation.ts` (from CITATION.cff) | Zenodo deposit metadata |
| `build/document-vX.Y.Z.pdf` | `scripts/tasks/compile.ts` | The compiled paper |

Editing any derived file by hand is a data-loss bug: the next build silently
overwrites it.

## 2. The build, end to end

A single command produces everything:

```bash
pnpm run build
```

Order of operations (`scripts/build.ts`):

1. `cleanupOldVersions` — clears `build/`.
2. `syncCitationMetadata` — reads `citation.csl.json`, writes
   `src/bibliography.bib` (BibLaTeX, keys renamed to the CSL `id`s), updates
   `CITATION.cff` and `.zenodo.json`.
3. `syncSelfCitations` — rewrites the marked self-citation regions of
   `README.md` (`badge`, `citation`) and of `main.tex` (`version`).
4. `syncCounts` — brings the marked count regions (`tests/README.md`) and
   `docs/counts.md` up to date with the working tree, so the PDF cannot
   print a stale number.
5. `compilePDF` — `latexmk -pdf` inside Docker (pinned image
   `kjarosh/latex:2024.4-full`, `SOURCE_DATE_EPOCH` from the commit; every
   reproducibility measure is `docs/architecture.md`); biber runs
   automatically through latexmk's `bcf → bbl` rule. The clean `vX.Y.Z`
   token is committed in `main.tex`; the `-dev@sha` form exists only in the
   rendered PDF (SPEC-004 §2).
6. `generateChecksums` — `checksums.txt`.

There are no manual steps. If the PDF is stale or the bibliography is
missing, fix the input (`citation.csl.json`, `main.tex`) and rebuild — never
patch intermediate artifacts.

## 3. LaTeX contract (`main.tex`)

The preamble of this repository, as built:

```latex
\usepackage{xcolor}\definecolor{linkred}{rgb}{0.78,0.08,0.12}
\usepackage[backend=biber,style=numeric,sorting=nyt,giveninits=true,doi=true,url=true,isbn=false]{biblatex}
\addbibresource{src/bibliography.bib}
\AtEveryBibitem{\iffieldundef{doi}{}{\clearfield{url}}}
\usepackage{hyperref}
\hypersetup{colorlinks=true,urlcolor=blue,linkcolor=linkred,citecolor=blue}
```

**Family standard, adopted.** All sibling repositories render with
`sorting=nyt,giveninits=true` (alphabetical, initials), and this
repository's `main.tex` now carries that line verbatim. It previously
carried `sorting=none` with no `giveninits` — order of first citation with
full given names — which was measured as a divergence and recorded as an
author decision; the standardisation wave then applied the family line, so
the divergence no longer exists. Both settings live in this one line of
`main.tex`; nothing else in the pipeline depends on them. The rendered
result (alphabetical order, given names as initials) is verified with
`pdftotext` against the built PDF at each change.

The body must NOT contain a manual `thebibliography` (this repository has
none, and no `\nocite`). The bibliography is printed from the database:

```latex
\printbibliography
```

Every `\cite{key}` key must exist as an `id` in `citation.csl.json`; biber
fails the build otherwise.

## 4. Adding a citation — checklist

1. Verify the metadata against authoritative sources first (Crossref REST
   API preferred; then OpenAlex, publisher pages, arXiv, zbMATH). Example
   batched verification:
   `https://api.crossref.org/works?query.bibliographic=...&rows=3&select=DOI,title,author,issued,page,volume,issue,container-title`
2. Append one CSL JSON object to `citation.csl.json`, keeping the array
   order stable (existing ids first, new entries appended).
3. Fields that apply to the type — omit, never null-pad:
   - `type`: `book`, `article-journal`, `posted-content` (preprint), …
   - `author`: array of `{"given": "...", "family": "..."}` objects.
   - `container-title`, `volume`, `issue`, `page`, `publisher`, `DOI`, `URL`.
   - `issued`: `{"date-parts": [[year]]}` — the PUBLICATION year, not the
     preprint year (the most common defect; arXiv year ≠ journal year).
   - `note`: series names (GTM 42, …) or scholarly remarks only.
4. `\cite{the-new-id}` in the text (or `\nocite` it deliberately).
5. `pnpm run build` and check the rendered entry in the PDF.

## 5. Data hygiene rules (lessons encoded)

- **Root title carries full Unicode**: `package.json.description` holds the
  paper title verbatim (this repository's: "Odd Zeta Values from Pentagonal
  𝔽₁-Descent: a Λ-structure on ℤ[φ], the character χ₅, and the zeta
  function"); every build copies it into `CITATION.cff` and the Zenodo title
  unmodified. Never ASCII-fold it — that degradation propagates to the
  deposition on every rebuild. The sanitizer applies only to Unicode
  superscripts (→ `<sup>`), never to math alphabetics or subscripts.
- **Author lists are structured.** Each author is one `given`/`family`
  object. A comma-joined blob ("A. X, B. Y, C. Z") makes biber abort with
  `Name "..." has too many commas` and kills the whole bibliography.
- **DOI without prefix**: `10.xxxx/yyy`, never `doi:10.xxxx/yyy`.
- **Do not force DOIs** that do not exist: most pre-1990 works and many
  classic books have none. Never use a review's DOI for the reviewed book,
  and never list series editors as book authors.
- **Preserve the published orthography** of titles (original spellings,
  Unicode names such as Özaydin, Pär); do not "modernise" them.
- **Name style inside `given`**: full given names preferred in stored CSL
  data (better Zenodo/CFF metadata); the rendered PDF abbreviates them to
  initials, because `main.tex` sets `giveninits=true` (§3). Long author
  lists abbreviate to "et al." by design.
- **DOI and URL**: both are stored in CSL/CFF/Zenodo metadata. In the
  rendered PDF the family hook
  `\AtEveryBibitem{\iffieldundef{doi}{}{\clearfield{url}}}` suppresses the
  URL whenever the entry has a DOI (no `doi.org` duplication); entries
  without a DOI keep their URL (retrieved-from sources).

## 6. Conventions

- Docs and comments in English; filenames kebab-case under `docs/`.
  **This repository commits no figure**: there is no tracked `images/`
  directory (the `figures` script in `package.json` refuses to run while
  `images/` carries tracked files), so the figure-naming convention of the
  siblings (`images/fig{N}_{semantic-name}.pdf`) has no instance here. What
  goes where — generic documents at the `docs/` root, repository-tied ones
  under `docs/reports/` — is the directory doctrine of `docs/README.md` and
  `docs/reports/README.md`; it is not restated here.
- Commits follow the family convention of `docs/usage.md` §Commits
  (Conventional Commits, English subject lines); scopes name the area, e.g.
  `docs(citations): add pipeline best-practices guide`,
  `fix(citations): correct Shou2023 author list and publication year`,
  `feat(paper): …`.
- Never push without an explicit instruction from the author.

## 7. Settled style decisions

- URL duplication with DOI in the rendered bibliography: **suppressed** via
  the `\AtEveryBibitem` hook (see §5); stored metadata keeps both.
- Reference ordering: **alphabetical** (`sorting=nyt`, the family
  standard, §3); rendered author names: **initials** (`giveninits=true` in
  this repository's `main.tex`).
- The gates that keep every layer honest: `pnpm run selfcitations:check`,
  `parity`, `counts:check`, `manifest:check` and `verify`, chained by
  `pnpm run validate`.

## 8. Witnesses (tiers)

The manuscript marks the status of each claim inline: an unbreakable tag set
in `\footnotesize` and bold, **without colour** (this repository's `\tier`
emits `{\footnotesize\textbf{[…]}}`; there is no colour dispatch). This
section is the contract of that device, written down here for whoever writes
or edits the text. The justification of the device — why a mark of this kind
belongs in a paper of pure mathematics, and what it does not claim — is
argued in `docs/witness-contract.md`; this section states only the contract.
The concrete instances of the rules below — site inventories, sentence
tails, applied states and verdict tables — live in `docs/reports/`.

The **set of evidence marks** is `P` and `N`, with `\testref` as the test
anchor — nothing else (`docs/witness-contract.md` §6.1); this repository's
preamble defines neither `\witness{…}` nor `\wtag{…}` (§8.1), so every
mark of the manuscript is inline by construction. Placement — inline or on
a line of its own — is a prose decision and never a semantic one (contract
§6.2), and the alphabet below is frozen at `P` and `N` (contract §6.8).

Measured state of the manuscript (2026-11-23; `git grep` over
`src/chapters/*.tex`, i.e. the body — the definitions in `main.tex`
excluded): `\tierP` 740, `\tierN` 123, marks carrying ids
`\tier[\testref{…}]{N}` **6** (over **7** ids), `\LeanInline` 992,
`\LeanStar` 221, `\LeanTally` 21, `\LeanCW` 44, `\leanline` 67; the retired
classes `\tierPnew`, `\tierC`, `\tierO`, `\tierT`, `\tierNc`, `\tier{R}`
appear **0** times. The seven cited test ids are pinned by
`tests/test_witness_census.py`, which fails when the manuscript's cited set
and the suite's node ids drift apart. The full per-file census of the closing
wave is in the MRG-001 closure report; re-measure with the same command
before quoting these figures.

### 8.1 Grammar — one macro, one optional argument

```latex
\tier{X}                -> [X]    the witness lives in the prose of the
                                   SAME sentence (a \testref, the name of
                                   one of our Lean declarations printed by
                                   \LeanInline/\LeanStar/\LeanTally/
                                   \LeanCW, an \eqref/\ref, a \cite)
\tier[\testref{ids}]{X} -> X[ids] the optional argument carries INTERNAL
                                   ids only, written inside a \testref:
                                   one id, or several separated by ',' —
                                   printed in tt inside the tag's own
                                   brackets
```

The optional argument means **internal ids and nothing else**, and in this
repository it must be a `\testref{…}`: the preamble tests the argument for
`\cite` first (an external key raises `\PackageError`) and then for
`\testref` (anything else — a bare token, a raw name not wrapped — raises
`\PackageError` with the message *Wrap the id in \testref*). The render of a
legal tag is therefore always the same shape: **the tag first, its ids
inside the brackets** — `N[test_x, test_y]`. The ids never precede the tag,
so a test witnessed in prose appears as `\tier[\testref{test\_x}]{N}`, never
as `(\testref{test\_x}) \tier{N}`.

Lean names are **not** written into the optional argument of `\tier` in this
repository: they are printed in the prose of the claim by the port's
decoration macros (`\LeanInline{name}` inline, `\LeanStar{name}` for the
pre-compilation provenance mark of §8.3, `\LeanTally{name}` for a tally,
`\LeanCW{name}` for a declaration of the companion development), and the tag
beside them carries the class. External sources stay outside the tag: the
claim keeps its `\cite` next to it, and a tag alone never carries a
reference number.

There is **no** `\witness{…}` block and no `\wtag{…}` label in this
repository's preamble (both are absent; `git grep -F '\witness'` over
`main.tex` is empty). Every mark of the manuscript is therefore inline by
construction — see §8.5 for what the family's own-line criterion means here.

`\Lean{}` is **defined** in the preamble (a right-aligned tt line) but has
**0 uses**; it is a definition kept for fidelity with the ported preamble,
not a device of the current text (F8-001 §1.3).

### 8.2 Rules for whoever writes or edits the text

1. **One claim, one tag.** No two tags are ever adjacent — `\tierP
   \tierN` is a bug, not a summary (measured: 0 adjacent pairs).
2. **An external source is the citation, not a tag — and never the key of
   one.** The source of a claim is its `\cite`, set immediately after the
   claim it supports. What a tag carries is an *internal* witness, by
   identifier: a `\testref{}` (inside the tag) or a Lean name in the prose
   of the same sentence. `\tier[key]{X}` does not exist — the preamble
   errors on anything that is not a `\testref`.
3. **A bare tag needs a witness in its sentence.** If the sentence has
   none, add the most honest one (the `\testref{}` of the test that checks
   the number, the Lean declaration that proves it, or an `\eqref`/`\ref`);
   never invent a citation.
4. **Every `\tierN` that a test verifies carries its `\testref{}`** —
   folded into the tag, `\tier[\testref{test\_x}]{N}`, or, when the
   sentence already carries other witnesses, as `\testref{}` in the prose
   of that same sentence, after the tag. The set of cited tests is pinned
   by `tests/test_witness_census.py`, so a new witness is added there too,
   after checking the test really recomputes the number next to it.
   **Applied state:** 6 marks / 7 ids are pinned today; the bare `N` sites
   whose sentences name no test are inventoried in `FTI-001` (finding 3)
   and remain open — they are not silently promoted to `N[ids]`.
5. **A `\tierP` without a bracket** means proved here, with no theorem
   name quoted at that point; the name, when it is quoted, is printed in
   the prose by `\LeanInline{…}` (or `\LeanStar`/`\LeanTally`/`\LeanCW`)
   beside the tag. Proved in an external source is not "here": the claim
   keeps its `\cite`.
6. **The gloss** defines the classes and nothing else — one sentence each.
   This repository's gloss sits before the first mark of the body
   (`01-introduction.tex`, *… `\tierP` marks a statement proved in Lean 4
   with Mathlib; `\tierN` marks a statement verified numerically, with the
   test named in the mark*) and is repeated in the *Protocol* subsection
   (`ssec:protocol`, *Two evidence classes are marked where a statement is
   stated*). It is exempt from rule 3 — it defines, it does not claim — and
   it never mentions `P*`.
7. **`P*` is not part of this text.** The class existed in the ported
   preamble (246 uses before the F11 reconciliation) and is **retired**:
   `git grep -F '\tierPnew'` over the manuscript returns 0 (F11b census
   `P* = 0`). What survives is the **star decoration** `\LeanStar{…}`
   (221 uses), whose `*` marks a name written but not yet verified against
   the corpus — the star's one denotation (contract §6.5): intermediate
   process state, resolved by the verification passes, and the release gate
   is zero stars. `F9-001` classifies the mark as a process artefact of the
   build (the modules compile in the green build), not a tier. Whether the
   221 `\LeanStar` uses are unified with `\LeanInline` is a presentation
   decision recorded for the author in the MRG-001 closure report; until it
   is taken, the star keeps that denotation and changes no claim.
8. **No status tags in captions.** A caption may name the test of the
   claim it states (`\testref{…}` of that claim's test); a `\tier{…}`
   inside `\caption{…}` is removed, not kept — tags belong to the body.
   **Applied state:** one caption still carries a tag
   (`03-mechanisms.tex`, the Fibonacci criterion figure); it was kept as
   `needs-decision` in `F8-001` §1.3 (the zip's preamble had no such rule)
   and is not changed here.

### 8.3 Alphabet

| Tag | Meaning |
|---|---|
| `\tier{P}` | proved and verified by machine (Lean) |
| `\tier{N}` | verified numerically |
| `\tier[\testref{ids}]{N}` | an `N` whose witness is a named test: `ids` is a `\testref` (several, separated by `,`), printed as `N[ids]` in tt by `\tier` itself |
| `\LeanInline{name}` | the Lean declaration of the claim, printed in tt in the prose beside the tag |
| `\LeanStar{name}` | same, with a superscript `*`: a name written but not yet verified against the corpus — intermediate process state, resolved by the verification passes, release gate zero stars (contract §6.5) |
| `\LeanTally{name}` | superscript `°`: a tally — a classification recorded in Lean as an enumerated type whose count is checked by decision; it certifies the count, not the classification |
| `\LeanCW{name}` | superscript `†`: a declaration of the companion development of `\cite{gonzalez26cw}`, not part of this paper's build |
| `\leanline{…}` | Lean accounting of a statement, set after it and outside the statement |

- **The decorations `°` and `†` are held** (contract §6.7): `\LeanTally` and
  `\LeanCW` keep rendering what they render today, but the decorations are
  not adopted into the evidence-mark set while their use stays marginal.

**Why there is no `L`.** A witness stresses that there *is* a reference, and
`P` and `N` earn their compactness by referencing by identifier — a theorem
name, a test name — while `L` only encodes "is cited", which the citation
itself already expresses and which costs a bracket more than it saves.

**Why there is no `R` (nor `C`, `O`, `T`, `Nc`).** Those classes were
carried by the ported shell and retired by the F11 reconciliation: each
repeated what the prose already said (a reading, an open step, a
literature assumption, a computer-assisted check) or named a status the
sentence states in words. `git grep` over the manuscript returns 0 for all
of them today (F11b census `C 0 · O 0 · T 0 · R 0 · Nc 0`); the prose
carries the word instead of the letter.

**The alphabet is frozen at `P` and `N`.** A new class enters only through
the family gate: measured sites, used *and* documented in all five
repositories, counted by `counts:check` and lintable, with the cost of
each new symbol estimated before it is admitted (contract §6.8). Until a
gate is passed, the alphabet does not grow.

**The hypothesis rule** (relocated here from the retired gloss, per
`FTI-001` §3.3): a `\tierP` mark certifies exactly the Lean statement it
names, **with its hypotheses** — when a declaration takes an input as a
hypothesis, that input is named with its own mark where it is stated. The
rule still governs the text: the appendix's ledger row *Reconnections of
compiled lemmas* and `05-categorical.tex` (*Hypotheses of compiled lemmas …
the rest carry their tier*) are written to it, and the appendix's
class-number row discharges a named hypothesis with its own `\tierP`.

### 8.4 Conventions of the device

- **Inline status is a convention of this project.** Each claim carries,
  next to it, how it was established — proved by machine, or computed and
  checked against a named test. That is a decision of this project and not
  an AMS or Chicago one; the real precedents are blueprints with a status
  per statement (`leanblueprint`), status tables and artefact seals
  (argued in `docs/witness-contract.md`). The gloss at the first mark
  therefore states the classes and nothing else.
- **Colour never carries meaning here.** This repository's tags are set in
  black like the surrounding text, so the WCAG 1.4.1 rule holds trivially:
  the letter alone always carries the meaning.
- **Canonical render parameters:** 13 pt for the witness class, 15 pt for
  the ids and 16 pt for the prose — the family's measured parameters
  (contract §6.6). This repository's tags are set in `\footnotesize`; their
  size is re-measured in the built PDF, never assumed.

### 8.5 Inline or a line of its own — the criterion

**In this repository every mark is inline, by construction.** The preamble
defines no `\witness{…}` block and no `\wtag{…}` label (§8.1), so there is
no own-line form for a mark to take. The family criterion below is stated
for completeness and for the sibling repositories that do define the block;
its own-line outcome has no form here yet.

Placement itself is prose — semantic, heuristic, aesthetic — and never a
semantic axis (contract §6.2): the criterion below measures cost and
position for that decision, it does not classify.

What the criterion produced when it was run over this manuscript is
recorded in `F8-001` §2: **1 100 marks** measured with the five quantities,
**856 inline / 244 own-line** verdicts, of which the 244 own-line ones are
`needs-decision` — the ported apparatus had no block to move them to, and
the decision (port `\witness`, or accept inline everywhere) belongs to the
author. Nothing was rewritten in block form on the strength of the
criterion alone (D4: *never in bloque*).

The rule in one sentence, as the family states it: a claim whose id list
carries **two ids or more and 35 characters or more** goes on a line of its
own `\witness{X}{ids}` **only if the mark closes its sentence, does not
close a list item, and stands at least 75 words from the nearest block of
its paragraph**; every other site stays inline. Four gates (`k ≥ 2`,
`L ≥ 35`, `r = 0`, `i = 0 ∧ d ≥ 75`) and two labelled heuristics (`u`
uniformity of the list the mark sits in, `p` paragraph close) decide it;
gates 1 and 3 are absolute. The quantities, the gates, the heuristics and
the review method are the family's (`05-kkgt/docs/citations.md` §8.5) and
are not restated here; the applied inventory — every site, its sentence
tail, its verdict — is `F8-001` §2.4 of this repository.
